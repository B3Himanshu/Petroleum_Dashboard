DOMAIN KNOWLEDGE — SAGE ACCOUNTING
────────────────────────────────────────────────────────────────────────────────
Deep familiarity with Sage 50 / Sage 200 chart-of-accounts conventions for the
petroleum sector:

  • Revenue codes (4000–4004): Petrol Unleaded, Diesel, Super Unleaded,
    Super Diesel, Adblue — stored as negative amounts in the audit journal
    (credit entries).
  • Bunkering codes (4100/4101/4102): BP commission charges, bunkered sales,
    bunkered commission — mixed sign convention (4100 + 4102 are costs paid
    TO BP, 4101 is bunkered fuel revenue).
  • Cost codes (5000–5005, 5041, 5046–5050): purchases, fuel commissions,
    stock movement per grade — stored as positive amounts.
  • Labour (7000–7005), Overheads (7100–7800), Depreciation (8200–8207),
    Loan Interest (7705/7750/7752/7753), Corporation Tax (9000).
  • Bank balance ranges (1200–1222) for closing-cash KPI.

This domain knowledge let me build correct profit calculations that match
the client's actual P&L — including the subtle "Charges deducted from Diesel"
rule that aggregates BP commissions into the diesel category for clean UI
display while preserving raw data.

DATA FLOW (CLIENT VALUE STORY)
────────────────────────────────────────────────────────────────────────────────
For a non-technical petrol-station owner, here is what the dashboard answers
in under 10 seconds:

  Q: "How much money came in this month?"
     → Total Site Revenue card. View breakdown shows split by fuel
        (per-grade), shop (per-product), coffee & valet (per-product).

  Q: "Am I making money on each grade of fuel?"
     → Gross Profit Breakdown modal — Unleaded vs Diesel vs Super grades
        vs Adblue. Charges (BP commissions) are netted into Diesel so the
        grade-level profit reflects what actually hits the bank.

  Q: "Is my pricing competitive enough? What's my margin per litre?"
     → Gross PPL card → currently 14.87p before overheads, 10.34p after.
        Trend chart shows whether it's improving.

  Q: "Where am I bleeding cash on overheads?"
     → Monthly Overhead Cost Trends — drill into 26 cost categories,
        identify outliers (e.g. credit charges spiking, repairs running hot).

  Q: "Which of my sites are performing best?"
     → Site ROI Trend, Metrics Comparison (Plotly bar), Site Comparison
        page (PPL, Labour %, Net Sales, photo gallery).

  Q: "What is my real net profit after every deduction?"
     → Total Net Profit card → EBITDA − Depreciation − Loan Interest −
        Corporation Tax, with full breakdown modal showing every nominal
        code that contributes.

  Q: "Are bunkering deals helping or hurting?"
     → Bunkered vs Non-Bunkered comparison charts (sales, volume, profit).

ENGINEERING HIGHLIGHTS — WHAT MAKES THIS PORTFOLIO STAND OUT
────────────────────────────────────────────────────────────────────────────────
1) Multi-tenant from a single codebase
   Same React + Express stack runs four clients with completely different
   nominal-code namespaces just by changing one env var (BASE_PATH=/hsrl,
   /prl, /pbfs) and remapping fuel-grade codes in a single config object.
   No code forks. No copy-paste rot.

2) Exact percentage reconciliation
   Implemented the Largest Remainder (Hamilton) method so child %s sum to
   parent %s exactly at any precision. Critical for trust — if a finance
   user adds the rows manually, they get 100.000%.

3) Mobile-first responsive charts
   Compressed 12 months of bars into 320 px wide screens without horizontal
   scroll. Y-axis labels rotate inside chart, x-axis ticks angle to -45°,
   tooltips reposition above the chart instead of overlapping data points.

4) Negative-sign awareness
   Sage's mixed sign convention (revenue negative, costs positive, except
   bunkering charges) was hand-mapped into UI logic. Charges show in red
   with a minus prefix, percentages reconcile correctly, totals match the
   client's actual P&L.

5) Performance & UX details
   Lazy-loaded site photos (loading="lazy" + decoding="async"), SVG
   placeholder fallbacks, glass-morphism cards with backdrop-blur, exact-
   precision percentage display (3+ decimals when value is < 0.05%).

6) Production-grade auth & email
   Email verification with token-hash storage, password-reset with single-
   use tokens, "show-error-as-200" pattern so login failures don't pollute
   the browser console with API URLs.

7) Documentation discipline
   Every substantive change appended to CHANGE_LOG.md with timestamp,
   files, details, and rollback instructions. Cursor rule auto-enforces.
   Documentation/ folder with ARCHITECTURE / NOMINAL_CODES /
   VOLUME_LOGIC / API / FRONTEND / CHANGES_INDEX.
