──── ADMIN LOGIN CARD ────────────────────────────────────────

Card Title:    "Admin sign in"
Card Subtitle: "Manage dashboard users (create / delete)."

FORM FIELDS:

  [1] Admin username
      Label:        "Admin username"
      Input type:   text   (not email — accepts email string)
      Autocomplete: username
      Required

      Label:       "Password"
      Input type:  password
      Autocomplete: current-password

  [5] Dashboard user sign in Button (outline)

PAGE 3: ADMIN DASHBOARD  →  Route: /admin
================================================================

URL:     /admin
File:    frontend/src/pages/AdminDashboard.jsx
Auth:    Requires admin JWT (redirects to /admin/login if missing)

──── PAGE LAYOUT ─────────────────────────────────────────────

Background:   bg-transparent (inherits app background)
Padding:      16px (p-4) mobile  /  32px (p-8) desktop
Max width:    896px (max-w-4xl), centered

──── TOP BAR ─────────────────────────────────────────────────

Left:
  Title:    "Admin — users"  (text-2xl, bold)
  Subtitle: "Create and delete dashboard users only."  (text-sm, muted)

Right (button group):
  [View dashboard]   → /dashboard           (default blue button)
  [Settings]         → /admin/settings      (outline button)
  [User login]       → /login               (outline button)
  [Admin logout]     → clears token, goes to /admin/login  (secondary button)

On mobile: buttons wrap to a second row


──── CARD 1: CREATE USER ─────────────────────────────────────

Card Title:       "Create user"
Card Description: "Initial password is returned once in a toast — save it.
                   User resets password only via email link."

Form layout:      2-column grid on sm+ screens, 1-column on mobile
Gap between fields: 16px

Fields:

  [1] First name
      Input type: text
      Placeholder: "First name"
      Max 100 chars
      Optional

  [2] Last name
      Input type: text
      Placeholder: "Last name"
      Max 100 chars
      Optional

  [3] Email                          (required)
      Input type: email

  [4] Initial password               (required)
      Label: "Initial password (min 8 chars)"
      Input type: password
      Min length: 8

  [5] Verification method            (spans both columns)
      Two radio buttons:

      ○ Verify from user
        "Send email with verification link (user must click to activate)."
        Value: "user_link"  ← DEFAULT

      ○ Direct verify
        "Mark user verified immediately and email them that account is active."
        Value: "direct"

  [6] Create user button
      Spans both columns
      Text: "Create user"  /  "Creating…" while loading
      Blue primary button

On success:
  - Toast: "User created"
  - Toast (info, 20s): "Copy initial password now: xxxxxxxx"
  - If email failed: Toast warning about SMTP config
  - If dev mode + no SMTP: Toast with verification URL link
  - Form resets to empty


──── CARD 2: USERS TABLE ─────────────────────────────────────

Card Title:       "Users"
Card Description: "X user(s)"  /  "Loading…"

Table columns:
  Name     |  Email  |  Verified  |  Actions

Each row:
  Name:     first_name + last_name (or "—" if empty)
  Email:    user's email address
  Verified: "Yes" if email_verified_at is set  /  "No" if null

Actions (per row):

  If NOT verified:
    [Verify]         → admin marks verified directly (with confirm dialog)
    [Resend verify]  → sends new verification email to user

  Always shown:
    [Update password]  → toggles an inline password edit row below
    [Delete]           → red destructive button, confirm dialog first

Inline password edit row (appears below user row when editing):
  - Password input: "New password (min 8 chars)"
  - [Save password] / [Cancel] buttons

================================================================
TOKENS STORED IN BROWSER
================================================================

localStorage key: "hsrl_admin_token"
  → Admin JWT token (7 day expiry)
  → Set on admin login success
  → Cleared on admin logout

localStorage key: "hsrl_admin_profile"
  → JSON: { id, email, username, firstName, lastName }
  → Set after admin login (fetched from /api/admin/profile)

sessionStorage key: "hsrl_auth_token" (or similar)
  → User JWT for regular dashboard access
